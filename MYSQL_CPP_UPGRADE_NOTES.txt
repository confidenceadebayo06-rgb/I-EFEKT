I-EFEKT — MySQL + C++ performance upgrade

WHAT CHANGED
- MySQL 8.4 replaces PostgreSQL as the main relational database.
- Prisma schema and Docker Compose now target MySQL.
- Added indexes for feed, follower, like/comment, story expiry, and message queries.
- Added a persistent C++20 worker for feed ranking. The worker is compiled with -O3 and receives bounded batches from the TypeScript API.
- The main /api/feed endpoint uses the C++ worker when available and safely falls back to chronological ordering if it is unavailable.
- Personal follow-affinity signals are used only when the user has opted into personalization.
- Added /api/feed/ranked and /api/engine/status.
- Added a repeatable native-engine benchmark command.

QUICK START
1. Extract the ZIP.
2. Copy .env.example to .env.
3. Start local services: docker compose up -d.
4. Install Node dependencies: npm install.
5. Build C++: npm run engine:build (requires g++/GCC or compatible C++20 compiler).
6. Generate Prisma client: npm run db:generate.
7. Create local MySQL tables: npx prisma db push.
8. Build TypeScript: npx tsc -p tsconfig.json.
9. Start server: npm run dev.
10. Open http://localhost:3000. Mailpit: http://localhost:8025.

PERFORMANCE CHECK
Run: npm run engine:benchmark
This benchmarks the C++ worker alone with 1,000 batches of 250 candidates. Results depend on hardware and are not a measure of total API, database, or video throughput.

IMPORTANT
- Switching from an existing PostgreSQL database to MySQL does not migrate existing records automatically. Export/transform/import data with a reviewed migration plan.
- The included Dockerfile uses Prisma db push for development bootstrap. For production, create/review versioned Prisma migrations and deploy with prisma migrate deploy.
- The TypeScript dependency install, Prisma validation, and full MySQL integration could not be completed in the build environment. The C++ worker was compiled and smoke-tested successfully.
- Media storage signing, live streaming/WebRTC SFU, EFK wallet/payment processing, and production security hardening still need provider integration and testing.
